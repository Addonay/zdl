# Validation, performance budgets and developer tooling

[Plan index](../../PLAN.md) · [Roadmap](12-migration-roadmap.md)

Status: proposed verification architecture. Numeric budgets below are **initial
design targets for named reference workloads**, not measured results or universal
performance promises. Establish the reference machine/environment in F0.

## Verification layers

1. **Pure model tests:** identities, transactions, documents, focus, capture,
   selection, layout, scrolling and semantic actions without a desktop/GPU.
2. **Failure/property tests:** allocation failure at every step, stale handles,
   arbitrary valid updates, malformed data, cancellation and teardown races.
3. **Backend contract tests:** the real text, paint, codec and accessibility
   adapters, with provider versions/fonts/output formats identified.
4. **Deterministic workflow replay:** real dispatch/reducer/update paths with
   recorded input and controlled time/completions, asserting semantic outcomes.
5. **Native integration:** actual compositor, IME, accessibility client, audio,
   controller, GPU or camera where that feature is claimed.
6. **Visual/performance/packaging:** fixed environment captures, representative
   measurements and a clean installation/dependency matrix.

Do not replace native integration with mocks, or replace model tests with screenshots.
A null audio target proves a useful route through ALSA, not speaker behavior.
An offscreen titlebar render cannot verify dragging/resizing under a compositor.

## Compile coverage and builds

Compile consumer bodies through representative **calls**, including generic
layouts/options and uncommon error paths. A reference such as `_ = decode` or
`refAllDecls` is not complete function-body coverage in Zig. Never execute the
compile-only backend consumer as a runtime smoke test.

During implementation, convert proposed public snippets into separately built
examples/consumers. Check core without libc and check optional C providers in
appropriate linked test roots. Test Debug and ReleaseSafe as a minimum; run
ReleaseFast/ReleaseSmall equivalence where optimized numeric kernels are involved.
The recent optimized-clamp regression is a reason to compare modes, not to assume
a scalar reference is correct merely because it is called “reference.”

Pin the compiler revision and dependency inputs for release evidence. Moving Zig
master adoption is a deliberate compatibility change, with std/API migration and
full consumer builds. Do not change the user's global compiler selection or add
unrequested build job limits.

## Key model/property suites

- Update abort at each allocation: old tree/IDs/focus/leases remain valid.
- Key reorder/insert/remove/kind change, generation wrap and owner mismatch.
- Document edit, selection, undo, composition and byte/native-offset round trips.
- Full versus incremental layout/paint equivalence within defined raster tolerance.
- Capture/gesture cancellation, modal routing and focus restoration.
- Virtualized item identity, estimated heights, anchor correction and AX reveal.
- Queue close/backpressure: each accepted ticket/payload disposed exactly once.
- Window/device loss while packets, font requests or semantic actions are pending.

Independent oracles matter. Codec hashes generated by the same defective decoder
are not independent correctness evidence. Unicode/provider fixtures, known image
corpora, hand-computable cases and a second implementation complement each other.

## Recording and replay

A recording includes ordered normalized events, copied payloads, monotonic origin,
window sizes/scales, locale, font/provider IDs and versions, asset content hashes,
model/document revisions and the completion sequence. Store protected text and
private paths only by explicit application policy; redact them by default.

Replay through ordinary UI dispatch/actions, not direct mutation of private
widget state. Assert meaningful outcomes before pixels: action count, document
contents/selection, focused node, modal scope, semantic roles/values and resource
lifetime. Store screenshot/semantic/display-list artifacts on mismatch.

Worker nondeterminism is controlled by recorded completion order or a deterministic
executor. Do not compare a replay using different fonts/fallback/version and call
its screenshot drift a rendering regression without classification.

## Visual testing

Pin fonts, provider/raster mode, color policy, logical size, scale and theme.
Fixtures include 1x/fractional/2x scale, light/dark/high contrast, RTL, long labels,
complex scripts, color glyphs, nested clips and alpha effects.

Use geometry and semantic snapshots alongside images. Compare exact values where
contracts are integer/deterministic; use documented perceptual/edge tolerances
for specific raster differences. A single permissive global threshold can hide
missing widgets, wrong text or stale frames. Review changed golden artifacts;
do not auto-bless screenshots when tests fail.

Cross-platform native font output is not expected to be pixel-identical. A
separate pinned embedded-font/provider configuration supplies portable image tests.

## Reference workloads

Maintain independently runnable scenes:

- Small settings app: 100 controls, real text editing, validation and a modal.
- Dashboard: charts, popups, 100k logical rows and live selection/filter changes.
- Text editor: a 10 MiB UTF-8 document, mixed scripts, long paragraphs and viewport
  edits; separate ordinary-field and pathological long-line measurements.
- Asset browser: thousands of logical thumbnails with bounded decode/upload work.
- Media view: moving video, overlays, seek/pause and UI changes under decode load.
- Graphics stress: clips, paths, shadows, layer transforms and text atlas pressure.
- Lifecycle stress: repeated windows, provider loss and cancellations.

Each scene states data shape, visible/materialized counts, update sequence,
resource policies and expected output. Do not reuse a static clear-screen demo
as the benchmark for an application toolkit.

## Initial target budgets

Reference profile: Linux desktop, fixed 1440x900 SDR window, named CPU/GPU/driver,
pinned fonts and providers. Measure software and accelerated modes separately.

- **Idle:** no periodic rendering and no toolkit timer wake without an active
  caret/animation/deadline; report wake counts and idle CPU over a fixed interval.
- **Warm interaction:** provisional UI-owner p95 <= 4 ms and p99 <= 8 ms for the
  defined settings/dashboard interactions at a 60 Hz presentation target.
- **120 Hz profile:** separate, more demanding targets, admitted only after
  measurement; a 60 Hz result does not imply 120 Hz support quality.
- **Virtualization:** materialized rows scale with viewport/overscan, not 100k
  logical items. Log actual nodes/materialized data, not just frames per second.
- **Steady updates:** no unnecessary heap allocation in unchanged hover/paint
  paths after warmup. Exceptions are identified rather than hidden in providers.
- **Memory:** bounded frame packets and explicit cache byte budgets. Report
  retained nodes, text/cache/CPU images/GPU/external-provider memory separately.
- **Startup/build size:** publish cold/warm first-interactive timings and actual
  binary/dependency deltas against an equivalent non-GUI consumer.

Budgets become release gates only after F0 calibrates hardware/workloads. Any
revision is a recorded decision with evidence, not an undocumented relaxation.
Do not label CPU submission latency as input-to-photon; compositor/display timing
requires separate instrumentation and clock-domain calibration.

## Benchmark discipline

Use repeated independent runs, warm/cold distinctions, percentiles and variation.
Record optimization mode, compiler, allocator, CPU features, power/affinity state,
provider versions, compositor, scale and asset/font data. Measure the full
operation including required ownership/setup/teardown as well as useful kernels.

Check output independently before accepting a faster implementation. Report
quality/precision and memory changes alongside throughput. Do not compare a
nearest-neighbor decoder/renderer against a higher-quality path as if they were
the same workload. Do not change global machine settings automatically.

Compare selected workloads with relevant Qt/GTK/egui/other native baselines only
where semantics, content, provider policy and measured stages are comparable.
Publish tradeoffs instead of a synthetic universal “fastest GUI” ranking.

## Developer tools

Provide optional, locally controlled inspection of:

- Node/key identities, hierarchy, role, state and source declaration location.
- Resolved style with provenance, constraints, intrinsic sizes and baselines.
- Hit-test/clip/transform and focus/capture/modal chains.
- Paragraph clusters, caret maps, fallback fonts and cache keys.
- Semantic tree, native bridge state and incoming action validation.
- Display-list batches, damage/layer dependencies, GPU resources/fences.
- Dirty reasons, per-stage time, allocations, cache misses and queue backpressure.

Inspector support is removable from production profiles. Remote inspection is
opt-in with an application-controlled endpoint; do not start a network listener
or expose protected text by default. Tools observe ordinary contracts and cannot
silently make an inaccessible control pass its tests through privileged mutation.

## CI and release evidence

Add lanes for core/no-libc, Linux headless, real text/codec providers, desktop
Wayland/X11, accessibility/IME, supported GPU drivers and packaging. Label absent
hardware lanes explicitly; a skipped driver lane does not become a passing badge
for that backend. Include dependency-absence and ABI-version rejection cases.

Store machine-readable evidence keyed by commit/compiler/profile. Preserve the
current finite run-target validator, extending it with GUI scenarios and explicit
provider checks. Keep correctness, hardware coverage, performance and visual
parity as separate statuses in the porting/release ledger.
